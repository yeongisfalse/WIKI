# Wiki 컴파일 규칙

- 핵심 용어 병기: 핵심 기술·연구 용어는 처음 등장할 때 한국어(영어 원문)로 병기하고, 표·목록의 주요 항목에도 필요하면 영어 원문을 함께 표시한다.
- 자료 유형 분류: 학술지·학회 논문과 문헌 리뷰는 wiki/papers/에, Editorial·Commentary·기사·블로그·일반 웹 문서는 wiki/web/에 컴파일한다. 수집 경로가 Web Clipper인지 여부는 raw/web/ 보관 위치와 별도로 관리한다.
- 논문 요약 파일명은 제목을 먼저 보여 주는 `<논문 제목> (발행연도).md` 형식을 기본으로 한다. 수집일·출처 도메인은 frontmatter와 `raw_file`에 남기며, raw 원본 파일명은 변경하지 않는다.

- 이 폴더는 AI가 유지하는 연구 지식 지도다. 원본을 복사해 쌓기보다 이해하기 쉬운 지식 단위로 컴파일한다.
- 분류: `topics/` 연구 주제, `concepts/` 핵심 개념, `papers/` 논문 요약, `web/` 웹 자료 요약, `methods/` 방법론, `ideas/` 연구 아이디어.
- `papers/`·`web/` 자료 요약 페이지에는 공통 핵심 내용, 출처와 맥락, 신뢰도와 근거, 혜영님의 연구와의 관련성, 연결 후보, 원문 및 출처 섹션을 둔다. `concepts/`·`methods/` 지식 페이지에서 개인화된 연구 관련성 섹션은 필수가 아니며, 내용상 필요할 때만 중립적인 적용 맥락으로 기록한다. 자료 유형에 맞는 선택 섹션을 추가한다.
- 신뢰도는 `high`, `medium`, `low`로 기록한다. `high`와 `medium`은 `proposals.md`에 연결·갱신 제안을 만들고, `low`는 그래프 연결 없이 요약만 만든다.
- `reviewed`·`stable` 페이지는 직접 덮어쓰지 않는다. `wiki/proposals.md`의 `approved` 항목만 명시적 승인 요청 후 반영한다.
- 처리 상태는 `.state/ingest-state.json`에서 `queued`, `processing`, `processed`, `failed`로 관리하며 원본에는 기록하지 않는다.
- 모든 위키 페이지는 `index.md`에 한 줄 요약과 함께 등록하고, 중요한 변경은 `log.md`에 남긴다. 제안·상태 파일은 인덱스에서 제외한다.
- 페이지 사이의 연결이 단순 요약보다 중요하다. 관련 근거·개념·방법·아이디어를 Obsidian 링크로 연결한다.

## 외부 학습 Vault 연계

- 기존 학습 Vault `/Users/Hyeyeong/Vault/`는 사람이 관리하는 원본으로 취급하며 AI가 수정·이동·삭제하지 않는다.
- 수업 필기·실습·프로젝트 전체를 복사하지 않고, 연구에 재사용할 가치가 확인된 노트만 HyeWiki에 독립적인 정제본으로 컴파일한다.
- 외부 Vault의 Obsidian 내부 링크·첨부파일에 의존하지 않는다. 정제본은 자체적으로 읽혀야 하며, 필요한 경우 `source_vault_paths`와 원본 학습 노트 섹션에 로컬 원본 경로를 기록한다.
- 외부 Vault 내용의 편입은 자동 동기화하지 않는다. 원본이 바뀌면 `wiki/.state/vault-import-state.json`의 해시와 각 페이지의 `source_vault_modified_at`을 비교해 수동으로 재검토한다.
- 수업 노트 기반 페이지는 외부 문헌이나 데이터로 재검증하기 전까지 기본적으로 `status: draft`, `confidence: medium`으로 둔다. 수식 조건·소프트웨어 버전·실습 결과를 확인하지 않았으면 `확인 필요`를 남긴다.
- 새 페이지가 기존 `reviewed`·`stable` 페이지와 연결되더라도, 기존 페이지에 역방향 링크를 추가하거나 내용을 갱신하는 것은 `proposals.md`에서 승인받은 뒤 수행한다.
